# CLX Portfolio SEO Plan

## Goal

Make `CLX`, `XCL`, and `CLX.I` discoverable as distinct but related
Clisonix products across:
- Google
- Bing
- DuckDuckGo
- GitHub
- PyPI
- developer docs search

## Core SEO Principle

Do not make all pages compete for the same exact keyword cluster.
Each product needs a different search intent and a different canonical page.

## Canonical Product Targets

### CLX

Primary search intent:
- Python package
- streaming toolkit
- nanodecibel metrics
- no-fake-data validation

Canonical page targets:
- `/developers/clx`
- PyPI package page for `clx`
- package README rendered on PyPI

Suggested title:
- `CLX Python Package | Clisonix Hotguard Streaming and Nanodecibel Metrics`

Suggested meta description:
- `CLX is the focused Clisonix Python package for hotguard
  streaming, nanodecibel metrics, stigma profiles,
  and no-fake-data validation.`

Primary keywords:
- `clx python package`
- `clx hotguard`
- `nanodecibel python`
- `no fake data validator python`
- `scanner printer stream python`

### XCL

## Information Architecture

Required landing pages:
- one canonical page per product
- one comparison page for `CLX vs XCL vs CLX.I`
- one developer docs index for all three
- one release notes hub for package and service updates

Internal linking rules:
- `CLX` page links to `XCL` for reasoning context
- `CLX.I` page links to `XCL` for domain enrichment explanation
- all three pages link back to a portfolio overview page

## Content Strategy

Top-of-funnel content:
- explain `nanodecibel` and why it matters
- explain no-fake-data guarantees in developer systems
- explain the difference between package, protocol layer, and service

Mid-funnel content:
- tutorials for `CLX`
- architecture articles for `XCL`
- API walkthroughs for `CLX.I`

Bottom-funnel content:
- release notes
- install guides
- comparison pages
- production deployment guides

## Technical SEO Checklist

- canonical tags on all product pages
- XML sitemap entries for product, docs, and release pages
- robots rules that allow indexing of public product pages
- Open Graph and Twitter metadata for all product pages
- stable slug naming with no duplicates
- package README aligned with page metadata
- GitHub repo descriptions aligned with page titles

## Product Messaging Rule

`CLX`, `XCL`, and `CLX.I` must not be described as the same thing.
Search engines and developers both need a clean semantic split.
